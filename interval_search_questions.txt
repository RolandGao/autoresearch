Understood: you want one search algorithm that works out sensitivity, cooldown, granularity and noise for itself, with no prior knowledge of the dataset or the hparams. The design below makes all five measured quantities rather than tuning knobs. The CIFAR results only serve as evidence for which mechanisms are needed.

The core idea: measure noise first, and express everything in units of it

Every decision compares proxy scores, so the one quantity everything else depends on is σ, the noise of a score difference. Since reruns are bit-exact, noise comes only from the seed (data order and augmentation), and σ can be measured directly. At each decision point, run the current config's proxy on 2 different data orders and keep a running pooled estimate.

Sensitivity, granularity, when to move and when to stop then all become ratios to σ.

1. Sensitivity → screening, then freezing

- Screening: at the first decision, and again every K decisions, probe each hparam with one wide step each way: ×10^±1 for LR-like (positive, log-scale) parameters, a matching step in log(1−m) for momentum-like ones.
- Sensitivity: S_p = the largest |score change| ÷ σ.
- Freezing: S_p < ~1 means the parameter can't be resolved, so it stays at its current value until the next screening.
- Ordering: active parameters are searched in decreasing S_p.

Screening costs 2 runs per parameter, and freezing stops compute going into noise. On CIFAR this would have kept conv LR and frozen nearly everything else.

2. Cooldown → a fixed rule, not a search

The cooldown's only job is to make a score at step t predict the final score. Fixed rule: after the candidate's main segment, scale every group's LR by a linear ramp from 1 to 0 over C steps, with C = the interval length.
- This removes the nested main/cooldown search loop.
- It has no hparams except C.
- It works for any number of groups.

Evidence: no cooldown fails, any cooldown fixes it, and searching the cooldown (interval2) didn't help.

The real obstacle is short-horizon bias. Even with a cooldown, a short lookahead always favours a lower LR: interval search cut conv LR every interval and never beat fixed linear
decay. This is a known effect (Wu et al. 2018, "short-horizon bias"). Two
- Search a scale on a decaying base shape (a multiplier on "decay to 0 over the remaining steps") instead of a constant LR per segment, so a candidate isn't rewarded just for
  decaying early.
- Lengthen the lookahead as the remaining budget shrinks. The proxy scores the cooldown endpoint, which is closest to what the final run produces.

3. Granularity → set by curvature and noise

- Grid step: start coarse, at the screening step. Refine (halve the log-step) once the best value is bracketed, meaning both neighbours score lower.
  - Fit a quadratic through the probes. Missing the peak by h/2 costs c·(he.
  - Stop refining once that cost is below σ, so the useful step size is h* ≈ 2√(σ/c).
  - A flat parameter gets a huge h*, which is the same as freezing it, so re one mechanism.
- Interval length: adjust it adaptively, like step-size control in an ODE solver.
  - If a decision didn't move the config by more than noise, double the in
  - If it moved two or more grid steps, halve it.
  - Every decision is a chance to drift on noise; on CIFAR the median best06 pp against 0.17 pp noise. Fewer decisions means less drift.

4. Noise → statistical decisions

- Hysteresis: keep the current value unless a challenger beats it by more
- Fit, don't pick: take the peak of the quadratic through the probes instead of the raw best point. It uses every evaluation.
- Racing: add seeds only to candidates whose interval overlaps the leader'uccessive halving), up to a cap. Replication goes only where a decision isclose and matters.
- Separate selection from reporting: score candidates on a held-out split, on.

5. Least compute

Compute comes from the pieces above, not from a separate knob:
- Screening costs 2 runs per parameter.
- Frozen parameters cost nothing.
- The fixed cooldown has no inner search.
- Refinement stops at the noise floor.
- Racing spends extra seeds only on close calls.
- Intervals lengthen as decisions stabilise.

Per decision the cost is about 2 noise replicates plus about 3 probes per , the algorithm could evaluate a candidate only when the chance it beatsthe leader by more than a tolerance is meaningful (an expected-improvement test).

Putting it together

init: θ = initial config, per-param log-step h_p = wide, interval L = T/5, σ = unknown
loop until T steps committed:
  σ ← pooled estimate from the current config's proxy on 2 data orders
  if first decision or K decisions since last screen: screen all params, f
  for p in active params by S_p:
      probe θ·e^{±h_p} with proxy = train L steps + linear-to-0 cooldown o
      race close calls (extra seeds), fit quadratic, move only if gain > 2σ
      refine h_p if c·(h_p/2)² > σ
  commit θ for L steps; L ← 2L if nothing moved beyond noise, L/2 if θ moved ≥ 2 steps
